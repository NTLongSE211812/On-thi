⚡ Bộ 5 Công Thức Vàng OSG202 (Gặp Là Bấm Ra Ngay)

Ch.2, 3, 4, 6
  • Độ sử dụng CPU đa chương: CPU Util = 1 - pn (n tiến trình, chờ I/O tỉ lệ p).
  • Lập lịch CPU: TAT = Finish - Arrival  |  WT = TAT - Burst.
  • Thời gian truy cập có TLB (EAT): α(tTLB + tMEM) + (1 - α)(tTLB + 2tMEM).
  • Số tài nguyên tối thiểu tránh Deadlock: Rmin = ∑(Maxi - 1) + 1.
  • Cây I-node: K = BlockSize / PtrSize ⇒ MaxBlocks = Direct + K + K2 + K3.

Mẹo Giải Nhanh
Chương Khi đề bài hỏi... Đáp án trọng tâm & Công thức ✅
Ch.1: OS & Syscall Chuyển từ User Mode → Kernel Mode? Giá trị trả về của fork()? • Chuyển chế độ qua lệnh TRAP (System Call).
• fork() trả về 0 cho Con, PID con (>0) cho Cha, -1 nếu lỗi.
Ch.2: Process/Thread Chuyển trạng thái nào KHÔNG tồn tại? Thread chia sẻ gì & có riêng gì? • KHÔNG có Blocked → Running và Ready → Blocked.
• Thread chia sẻ: Code, Data, Heap, Files | Có riêng: Stack, Registers, PC.
Ch.2: Scheduling Tính CPU Utilization với n tiến trình chờ I/O tỉ lệ p & Real-time Schedulable? • CPU Util = 1 - pn (VD: 4 tiến trình, p=0.5 ⇒ 93.75%).
• Real-time lập lịch được khi ∑ (Ci / Pi) ≤ 1.
Ch.3: Paging & TLB Dịch địa chỉ ảo V sang vật lý? Tính Effective Access Time (EAT)? • Page = ⌊V / PageSize⌋, Offset = V mod PageSize ⇒ PAddr = Frame × PageSize + Offset.
• EAT = α(tTLB + tMEM) + (1 - α)(tTLB + 2tMEM).
Ch.3: Replacement Thứ tự đuổi trang NRU? Belady's Anomaly xảy ra ở đâu? • NRU đuổi lớp nhỏ nhất trước: Class 0 (R=0, M=0) → Class 1 (0,1) → Class 2 (1,0) → Class 3 (1,1).
• Belady's Anomaly (tăng frame tăng fault) xảy ra ở FIFO.
Ch.4: File Systems Phân biệt Hard Link vs Symbolic Link? Tính kích thước Bitmap? • Hard Link: cùng i-node, cùng partition, xóa gốc vẫn đọc được.
• Symbolic Link: chứa đường dẫn, xuyên partition, xóa gốc bị hỏng link.
• Bitmap (bytes) = (DiskSize / BlockSize) / 8.
Ch.5: I/O & Disk 4 tầng phần mềm I/O (từ dưới lên)? Cơ chế truyền cả khối không qua CPU? • 4 tầng: Interrupt Handlers → Device Drivers → Device-Independent → User-Space.
• Truyền cả khối trực tiếp vào RAM: DMA (Direct Memory Access).
Ch.6: Deadlocks 4 điều kiện Coffman? Số tài nguyên tối thiểu Rmin để không bao giờ Deadlock? • 4 ĐK: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait.
• Công thức tránh Deadlock: Rmin = ∑(Maxi - 1) + 1.

🐧 Sổ Tay Các Lệnh Linux / Ubuntu Hay Gặp Trong OSG202

POSIX / Shell

📁 Quản Lý File, Thư Mục & Phân Quyền

  • ls -la — Liệt kê tất cả file (gồm file ẩn) + quyền + kích thước
  • cd .. / pwd — Về thư mục cha / In đường dẫn hiện tại
  • mkdir dir / rm -rf dir — Tạo / Xóa thư mục đệ quy
  • cp a b / mv a b — Sao chép / Di chuyển hoặc đổi tên
  • ln src dst / ln -s src dst — Tạo Hard Link / Symbolic Link
  • chmod 755 file — Đặt quyền rwxr-xr-x (r=4, w=2, x=1)
  • chown user:group file — Đổi chủ sở hữu file

⚙️ Quản Lý Tiến Trình, Tìm Kiếm & Hệ Thống

  • ps -ef / top — Xem danh sách tiến trình đang chạy & PID
  • kill -9 PID — Buộc kết thúc ngay lập tức tiến trình (SIGKILL)
  • grep "text" file — Tìm dòng chứa chuỗi khớp trong file
  • cat file | wc -l — Đếm số dòng bằng ống dẫn Pipe (|)
  • df -h / du -sh — Xem dung lượng phân vùng / thư mục
  • fsck /dev/sda1 — Kiểm tra & sửa lỗi nhất quán File System
  • man ls — Mở trang hướng dẫn chi tiết (Manual) của lệnh

⏱️ 1. Mô Phỏng Lập Lịch CPU (FCFS, SJF, SRTN & Round Robin)

Nhập mỗi dòng: Tên Arrival Burst → Tự vẽ Sơ đồ Gantt & tính Average TAT / Waiting Time.

📄 2. Dịch Địa Chỉ Paging (Ảo → Vật Lý) & Tính TLB EAT

Tự động tách Page Number, Offset, tính Physical Address và thời gian truy cập trung bình EAT.

🔄 3. Mô Phỏng Thay Thế Trang (FIFO, LRU & Optimal)

Nhập chuỗi tham chiếu trang & số khung trang (Frames) để so sánh số Page Faults của cả 3 thuật toán.

🏦 4. Thuật Toán Banker (Kiểm Tra Safe State & Safe Sequence)

Hỗ trợ cả 1 loại tài nguyên hoặc nhiều loại (A B C). Mỗi dòng là 1 tiến trình P0, P1, P2...

💿 5. Lập Lịch Đầu Đọc Đĩa Cứng (FCFS, SSTF & Elevator/LOOK)

Tính tự động thứ tự phục vụ và tổng quãng đường di chuyển đầu đọc (Total Head Movement).

🧩 6. Cấp Phát Bộ Nhớ (First/Best/Worst Fit) & I-Node File Size

Kiểm tra lỗ trống được chọn và tính kích thước file tối đa của I-node UNIX/Linux.
